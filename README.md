# ClockworkGit

Git-клиент для личного пользования в духе SmartGit: та же раскладка окна, граф коммитов, ветки,
основные операции — плюс нормальная работа с картинками и Git LFS для игровых и веб-проектов.

Написан на C# / [Avalonia](https://avaloniaui.net/) 11, работает через обычный `git` из командной строки,
поэтому учитывает ваш `.gitconfig`, хуки, менеджер учётных данных и LFS.

## Быстрый старт

1. Установите [Git for Windows](https://git-scm.com/download/win) и [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).
   Для репозиториев с Git LFS дополнительно установите [Git LFS](https://git-lfs.com/) и выполните `git lfs install`.
2. Из каталога исходников запустите ClockworkGit, передав путь к корню рабочей копии существующего репозитория:

   ```powershell
   dotnet run -- "C:\path\to\repository"
   ```

   Путь можно не указывать: приложение откроет последний выбранный репозиторий. Новый репозиторий добавляется через
   **Repository → Add Repository…**.
3. Выберите репозиторий слева. В дереве **Branches** отметьте ветки, историю которых нужно показать в графе.
   Выберите коммит или **Working Tree**, чтобы посмотреть список файлов и diff.
4. Выберите файлы и нажмите **Stage**, затем **Commit**. Для отправки изменений используйте **Push**; перед получением
   обновлений — **Fetch** или **Pull**. **Discard** отменяет изменения в рабочей копии и требует подтверждения.

## Возможности

**Главное окно**
- Список репозиториев со статусом каждого: «✎3» изменённых файлов, «↑1» к push, «↓2» к pull (синим, когда на remote
  есть новое); в подсказке — подробности и время последнего fetch.
- Фоновый fetch всех репозиториев по очереди (Repository → Auto-fetch: выкл / 5 / 10 / 30 минут, по умолчанию 10)
  и «Fetch all repositories now». Окно логина в фоне не всплывает (`GCM_INTERACTIVE=never`) — ошибка видна значком ⚠.
  Открытый репозиторий после fetch обновляется сам.
- Дерево веток (локальные с папками, remote, теги, стеши) с ahead/behind.
- Граф коммитов с линиями веток и мержей, метки веток/тегов, аватары с инициалами авторов,
  фильтр по теме коммита, автору, началу хеша и именам ссылок. При фильтрации линии графа скрываются.
  Галочка у ветки добавляет её историю в граф.
- Детали коммита, список изменённых файлов с сортировкой по имени или пути, бейдж **LFS** и фильтр «LFS only».
- «By project» группирует файлы по проектам: самая внешняя папка с отслеживаемым `*.csproj`, `*.fsproj`,
  `*.vcxproj`, `package.json` или Unity `ProjectSettings/ProjectVersion.txt`. Вложенный ClientApp входит в
  родительский проект. Файлы-маркеры без каталога (`*.csproj`, `package.json` и т. п.) игнорируются. Файлы вне проектов
  группируются по папке верхнего уровня. Клик по заголовку выделяет все файлы группы — удобно для Stage/Unstage
  одного сайта. Включается отдельно для каждого репозитория.
- Diff снизу: side-by-side с подсветкой изменённой части строки; для картинок — сравнение изображений.

**Операции**
- Pull, Sync (pull + push), Push (с `-u` для новой ветки), Fetch.
- Commit / Amend / Commit & Push, Undo Last Commit (`reset --soft`, сообщение предлагается снова).
- Stage, Unstage, Discard (с подтверждением; новые файлы удаляются с диска только после него).
  Если файлы не выбраны, Stage и Unstage применяются ко всему репозиторию; Discard требует выбора файлов.
  Discard возвращает отслеживаемые файлы и их индекс к HEAD, а новые файлы (включая уже добавленные в индекс) удаляет.
- Частичный stage: в diff рабочей копии режимы Unstaged / Staged / All, кнопки «Stage block» (`Ctrl+B`),
  «Stage lines» (`Ctrl+L`), в режиме Staged — Unstage, в Unstaged — «Discard lines…». Строки выделяются
  мышью с Ctrl/Shift; патч из выбранных строк применяется через `git apply --cached`.
- Из графа: checkout коммита, создание ветки/тега, cherry-pick в текущую или выбранную ветку, revert,
  reset soft/mixed/hard. Из дерева: checkout (в т.ч. remote с трекингом), merge, rebase, rename, delete.
- Интерактивный rebase: ПКМ по коммиту → «Interactive rebase from here…». Для каждого коммита Pick / Reword /
  Squash / Fixup / Drop, перестановка (Alt+↑/↓), правка сообщения. Выполняется настоящим `git rebase -i --autostash`
  без редактора: todo подставляется через `GIT_SEQUENCE_EDITOR`, сообщения — через `exec git commit --amend -F`.
  Выбранный коммит включается в диапазон; допускается до 500 коммитов. Merge-коммиты не поддерживаются.
  Если начальный коммит найден в локальных remote-tracking ветках — предупреждение. При конфликте работает
  плашка Continue/Abort; прежняя история может быть доступна в Recyclable Commits.
- Push после rebase/amend: при отказе с признаками non-fast-forward клиент предлагает `push --force-with-lease`.
- Stash: save, apply, pop, drop. Save сохраняет отслеживаемые изменения; неотслеживаемые файлы не включаются.
- Recyclable Commits: вершины цепочек коммитов, потерянных после Undo/amend/reset/rebase, но ещё достижимых из reflog
  (`git log --reflog --not --all`). После удаления ветки они видны, если сохранились в другом reflog, например HEAD.
  Предполагаемая причина («reset: moving to HEAD~1», «commit (amend)») показывается, когда её удаётся определить.
  Галочка или двойной
  клик выводит коммит в граф с меткой ♻; можно создать на нём ветку, сделать cherry-pick или вернуть ветку на него
  (`reset --keep`: Git откажет, если операция перезапишет локальные изменения).
  Это временная возможность восстановления: срок зависит от настроек и очистки reflog и объектов.
  Для недостижимых записей reflog стандартный срок истечения — 30 дней, но это не гарантия хранения коммитов
  ([документация Git](https://git-scm.com/docs/git-reflog#Documentation/git-reflog.txt---expire-unreachabletime)).
- Конфликты: плашка Resolve… / Continue / Abort для merge/cherry-pick/revert/rebase.
- Редактор конфликтов (двойной клик по конфликтному файлу): стадии индекса заново сливаются `git merge-file --diff3`,
  так что непересекающиеся правки уже влиты; каждый конфликт — карточка «Ours | Base | Theirs» с кнопками
  Ours / Theirs / Ours + Theirs / Theirs + Ours / Base / Neither и редактируемым результатом, Prev/Next (F7).
  Подписи сторон учитывают операцию (при rebase ours — ветка-основа, theirs — воспроизводимый коммит).
  «Save & mark resolved» записывает UTF-8 и делает `git add`: CRLF выбирается, если он встречается в текущем файле
  на диске, иначе LF; BOM определяется по результату слияния. «Save with markers» сохраняет текущий результат
  без добавления в индекс, оставляя маркеры у нерешённых конфликтов. Бинарные файлы и удаление с одной стороны решаются выбором версии,
  картинки при этом показываются сравнением.

**История файла и Blame** — в контекстном меню файла «History…» / «Blame…»
- History: до 2000 коммитов от HEAD, менявших файл (`git log --follow`, с переименованиями), детали и diff выбранного коммита,
  для картинок — сравнение изображений; «Blame at this revision», «Open in compare window».
  Выбранный в основном графе коммит задаёт начальную ревизию blame, но не ограничивает историю файла.
- Blame: у каждой строки коммит, автор и дата, полоса слева теплее у свежих правок. Двойной клик открывает
  коммит строки в History; «Blame before this change» показывает файл до правки, давшей эту строку
  (как Investigate в SmartGit), кнопка «← Back» возвращает назад.

**Unity**
- Проверки перед коммитом (внутри `Assets/` каждого проекта, найденного по отслеживаемому `ProjectSettings/ProjectVersion.txt`):
  новый ассет или папка без `.meta`, новая `.meta` на диске, но не в коммите, осиротевшая `.meta`, удалённый ассет с
  оставшейся `.meta` и — самое опасное — удалённая `.meta` у живого ассета (Unity выдаст новый GUID, ссылки
  сломаются). Плюс файлы больше 10 МиБ вне LFS в любом репозитории. Предупреждения видны в диалоге коммита
  (с галочкой «Also stage the N .meta file(s)») и строкой в деталях Working Tree.
  Проверки используют статусы, размеры и наличие файлов на диске и атрибуты рабочей копии; они не анализируют
  точное содержимое будущего коммита при частичном staging и не блокируют коммит.
- В diff `.mat`, `.prefab`, `.unity`, `.asset`, `.asmdef` и других файлов со ссылками `guid: …` справа от строки
  показывается имя ассета: «→ ash_body_basecolor.png», полный путь — во всплывающей подсказке. Индекс GUID → путь
  строится из отслеживаемых и неигнорируемых неотслеживаемых `.meta`-файлов на диске при первом подходящем diff.
  Индекс старше двух минут перестраивается при следующем обращении. При непустом индексе встроенные ресурсы
  Unity помечаются как «built-in», неизвестные GUID — как «missing asset». Для старых коммитов используется
  тот же индекс текущей рабочей копии.

**File Compare** — двойной клик по файлу (или кнопка «Open in compare window»)
- Файл целиком, строки выровнены, полоса-обзор изменений справа, Prev/Next Change, Ignore whitespace.

**Картинки**
- Side by side, onion skin, попиксельная разница; масштаб Fit / 25–800 %, синхронная прокрутка, шахматный фон.
- Форматы: PNG, JPG, BMP, GIF, WebP, ICO, TGA, а через Magick.NET — SVG, PSD/PSB (сведённое изображение),
  TIFF, EXR/HDR, DDS, AVIF, HEIC, JXL и другие. SVG можно смотреть и как текст.
- Каналы RGBA / RGB / R / G / B / A для упакованных текстур (MetallicSmoothness, маски): RGB показывает цвет
  и под прозрачными пикселями, отдельный канал — в оттенках серого; разница считается только по выбранным
  каналам. В строке информации видно, используется ли альфа вообще.
- Для изображений разного размера разница и процент изменённых пикселей считаются только в общей области
  от верхнего левого угла; изменение размера отмечается отдельно.

**Git LFS**
- Track/Untrack правил из контекстного меню файла, с необязательной конвертацией уже отслеживаемых файлов
  (`add --renormalize`). В индекс добавляется весь корневой `.gitattributes`, а при конвертации — текущие
  версии соответствующих файлов вместе с локальными правками. Старые версии остаются в истории;
  Untrack не удаляет ранее загруженные объекты с сервера, и на файлы могут продолжать действовать другие правила LFS.
- Окно LFS: `git lfs ls-files --json HEAD` с размерами и признаком наличия объекта в локальном хранилище LFS
  (это не проверка развёрнутого содержимого файла в рабочей копии), правила корневого `.gitattributes`, размер кэша,
  поиск файлов под правилами, которые ещё лежат обычными blob'ами, и их перевод в LFS без переписывания
  истории. Для отсутствующих в кэше объектов доступна выборочная загрузка через контекстное меню (`git lfs pull --include=…`).
  `git lfs fetch --all` загружает с сервера по умолчанию объекты истории всех локально известных ссылок,
  не обновляя рабочие файлы ([документация Git LFS](https://github.com/git-lfs/git-lfs/blob/main/docs/man/git-lfs-fetch.adoc)).
- Блокировки LFS: бейдж «🔒 you» / «🔒 имя» в списке файлов, Lock / Unlock / Force unlock в подменю LFS файла,
  вкладка Locks в окне LFS, число блокировок в статусной строке, предупреждение перед коммитом файла под чужой
  блокировкой. Список запрашивается через `git lfs locks --verify --json` при открытии репозитория, после фонового
  fetch и действий с блокировками; его также можно обновить вручную. Окно входа GCM отключено.
  Если verify не сработал, используется `git lfs locks --json`, и все блокировки считаются чужими, поскольку
  владение не проверено. При ошибке обновления основное окно сохраняет последний известный список.

## Сборка и запуск

Для сборки нужны [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и [Git for Windows](https://git-scm.com/download/win)
версии 2.40 или новее (используется `check-attr --source`). Для функций Git LFS также нужен
[Git LFS](https://git-lfs.com/). Без него можно работать с репозиториями, которым не требуются фильтры LFS.

Из корня проекта:

```bash
dotnet restore
dotnet build -c Release
dotnet run -- "C:\path\to\repository"
```

Аргумент после `dotnet run --` — необязательный путь к корню рабочей копии: он добавляется в список и открывается.
Если аргумент не задан, приложение открывает последний выбранный репозиторий. Репозитории также можно добавлять
из окна приложения кнопкой **Add Repo**.

Для публикации под Windows x64:

```bash
dotnet publish -c Release -r win-x64 --self-contained false -o publish
```

При `--self-contained false` на компьютере, где запускается опубликованная версия, должен быть установлен .NET 8 Runtime.
Публикация под конкретную платформу уменьшает размер: Magick.NET в варианте AnyCPU включает нативные библиотеки для
нескольких платформ.

Настройки (список репозиториев, отмеченные ветки, сортировка) — в `%APPDATA%\ClockworkGit\settings.json`.

## Устройство

Каждое пространство имён соответствует папке, общие `using` — в `GlobalUsings.cs`.

| Папка | Что внутри |
|---|---|
| `Git/` | `GitRunner` (запуск git без интерактивных запросов), `GitRepo` (partial: история, diff, blame, конфликты, LFS, Unity), `GraphBuilder` (раскладка графа по линиям), `DiffParser` (unified diff → строки side-by-side), `PatchBuilder` (патч из выбранных строк), `RebaseTodo` (план rebase без редактора), `MergeFileParser`, `RepoSummary` |
| `Models/` | Данные: коммиты, ссылки, изменённые файлы, строки diff, LFS-записи |
| `ViewModels/` | Узлы дерева веток, строки списков для привязки в XAML |
| `Views/` | Окна: `MainWindow` (partial по областям: Repositories, AutoFetch, Refresh, Branches, Details, Staging, Operations, Rebase, Conflicts, Locks, ContextMenus), `FileCompareWindow`, `FileHistoryWindow`, `ConflictEditorWindow`, `InteractiveRebaseWindow`, `LfsWindow`, диалоги |
| `Controls/` | Отрисовка графа, текст строки diff с подсветкой, полоса-обзор, сравнение картинок |
| `Imaging/` | Декодирование (Skia, TGA, Magick.NET), попиксельная разница, перенос в Avalonia |
| `Services/` | Настройки, сценарии Track/Untrack для LFS |
| `Unity/` | Индекс GUID → путь ассета из `.meta` для подписей в diff |
| `Utils/` | Форматирование, открытие в Проводнике, пункты контекстного меню |

Команды Git выполняются через CLI; файлы настроек, рабочей копии и локальный кэш также читаются напрямую.
Для status, списков путей и check-attr используется NUL-разделение (`-z`); некоторые другие команды,
включая историю файла, разбираются построчно. `GitRunner` передаёт аргументы через `ProcessStartInfo.ArgumentList`,
читает stdout/stderr параллельно и отключает запросы Git в терминале и редакторы. Для фоновых запросов
отдельно задаётся `GCM_INTERACTIVE=never`. Таймауты и отмена процессов пока не предусмотрены.

Загрузка данных асинхронна; в основных представлениях счётчики поколений отбрасывают устаревшие результаты,
но не останавливают уже запущенную работу. Большинство изменяющих действий главного окна проходят через `Do()`:
защита от повторного входа, отключение тулбара, показ исключения и обновление данных после действия.
Окно LFS выполняет свои действия отдельно и уведомляет главное окно обратным вызовом.

XML-комментарии можно проверить компилятором без предупреждений о недокументированных публичных свойствах:

```powershell
dotnet build -c Release -p:GenerateDocumentationFile=true -p:NoWarn=1591
```

## Ограничения

- Интерактивный rebase не переносит merge-коммиты и не умеет останавливаться на коммите для правки (`edit`).
- Частичный stage недоступен для неотслеживаемых и конфликтных файлов, а также до первого коммита — они добавляются целиком.
- Сравнение изображений рабочей копии и отдельное окно File Compare используют HEAD и файл на диске;
  режимы Staged/Unstaged нижней текстовой панели на них не распространяются.
- Список LFS-файлов относится к HEAD; изменения, только что добавленные в индекс, появятся в нём после коммита.
  Наличие LFS в атрибутах файла проверяется отдельно от наличия указателя в HEAD.
- Список правил LFS читает только корневой `.gitattributes` и разбирает его упрощённо. Сопоставление правил
  в интерфейсе поддерживает `*`, `**` и `?`, но не всю семантику Git. Фактический атрибут `filter` запрашивается через `git check-attr`.
- Размер кэша вычисляется по `<git-dir>/lfs/objects`; пользовательская настройка `lfs.storage` не учитывается.
- Используется SHA-1 пустого дерева; поддержка репозиториев с форматом объектов SHA-256 не реализована.
- Группировка по проектам некорректно обрабатывает Unity-проект в корне репозитория: его маркер определяется
  как каталог `ProjectSettings`. Вложенные Unity-проекты распознаются по родительскому каталогу.
- В граф загружается до 2000 последних коммитов отмеченных веток.
- PSD показывается сведённым изображением, без слоёв.
- Только Windows (Проводник, иконки Segoe Fluent).
